## Anti-Patterns Verdict

整体并非明显的 AI 模板化界面，现有设计系统、留白、分组和组件复用都较稳定。但“今日安排”卡片存在局部模板化问题：浅色圆角卡片、闪光图标和一句数据复述营造了“智能洞察”的视觉暗示，实际只是 Event 数量、标题和逾期 Task 数量的拼接。

静态探测器对目标文件返回 0 条规则命中；这只能说明未发现其规则库覆盖的源码反模式，不能否定运行时的信息架构、状态矛盾或交互问题。浏览器覆盖层因 URL 策略阻断注入前置检查，未获得可见的运行时叠加证据。

## Overall Impression

“今天要做”和“今日安排”对用户而言确实重复。它们在数据上分别偏向 Task 和 Event，但当前页面没有把这种领域差异转译成清楚的用户语言，反而让两个模块都像是在回答“我今天有什么”。

成熟应用会同时呈现任务与日程，但通常只选择一种清晰模型：统一的时间轴、同一页面中明确分开的任务区与日程区，或 Calendar / To Do 标签切换。很少用两个近义标题、两种空状态和一个含混的总括卡片并列竞争。

当前产品文档把首页定义为“今天优先做什么”，并明确 Today Tasks 只收 Task、Event 从计划日历查看。因此，现阶段最一致的做法是保留“今天要做”，移除当前“今日安排”摘要；若未来实现真正的 Daily Brief，应以“今日提醒”呈现少量有依据、可行动的观察，而不是重复 Event 数量。

## 成熟产品对照

| 产品 | 采用的模型 | 对本项目的启示 |
|---|---|---|
| Things 3 | Today 以待办为主，可把日历事件放在顶部，但事件与待办明显分开。 | 可以同页共存，前提是对象与视觉层级清楚。 |
| Todoist | Today / Upcoming 可显示外部事件；列表视图把事件集中在顶部，日历视图按时间块呈现。 | 选择一个统一容器，并明确 Event 的只读或可操作边界。 |
| Outlook My Day | Calendar 与 To Do 使用独立标签。 | 当两类对象操作模型不同，切换比近义模块并列更清楚。 |
| Google Calendar | 有日期的任务可以进入日历并直接完成。 | 若要融合，应真正做到统一时间视图与状态操作。 |
| Apple Calendar + Reminders | 提醒事项仍是独立对象，但可显示在日历中。 | “数据联动”不等于“概念合并”。 |

## What’s Working

- Today 排序和收录由服务端权威逻辑负责，避免移动端自行拼规则。
- 任务默认展示前四项并允许展开，符合渐进披露。
- 页面组件、可访问性标签和基础视觉语言总体一致。
- Task 与 Event 在数据层已经分开，信息架构可以调整而无需先重构领域对象。

## Priority Issues

### P1：近义模块制造事实矛盾

在无 Task、有 Event 的情况下，“今天要做”的空状态会显示“今天还没有安排”，而“今日安排”又显示“今天有 N 个日程”。这不是单纯的重复，而是同屏互相否定，会直接损害用户对首页信息的信任。

### P1：“今日安排”承担了三个不相容的角色

该卡片同时摘要 Event、显示逾期 Task 数量，并使用闪光图标暗示 AI Daily Brief；但整张卡片只跳转日历。信息来源、动作目标和视觉承诺不一致，用户看到逾期项也无法从该入口直接处理。

### P2：首页缺少唯一首要决策

顶部标签、提醒、八个同权快捷入口、任务分组和“今日安排”依次争夺注意力。对一个应回答“现在先做什么”的页面而言，用户要扫描太多入口后才抵达主要任务。

### P2：关键状态反馈不足

任务完成动作缺少明确的 pending、失败恢复与撤销。对于高频列表，成熟体验通常会提供乐观反馈和短时撤销，以降低误触成本。

### P3：可读性与触控细节

部分辅助文字尺寸偏小；长标题与动态字体下需复核截断；紧凑行和图标按钮需验证至少 44×44 的触控区域。

## Cognitive Load Review

八项检查中有五项未通过：单一焦点、信息分块、视觉层级、一次只做一件事、最少选择。分组、工作记忆负担和渐进披露基本通过。主要负担不是页面元素太多，而是多个元素都在争夺“今天的总览”这一相同语义位置。

## Emotional Journey

首屏视觉干净，初始感受可靠；继续向下扫描时，提醒和八个入口推迟了核心任务。最大的信任低谷出现在“今天还没有安排”与“今天有 N 个日程”并存时。页面末尾用通用摘要卡收尾，也没有给用户一个明确的“下一步做什么”。

## Persona Red Flags

- 新用户会难以理解 Today 标签、“今天要做”“今天有安排”“今日安排”四种近义表达的区别。
- 高频用户希望迅速扫描并处理任务，但必须先越过多个同权入口；误完成后也缺少撤销。
- 跨领域管理用户需要一个权威的“现在”入口；Event、逾期 Task 与 AI 暗示混在一起，会削弱系统可信度。

## Minor Observations

- `scheduled_today` 面向用户可改为“今天已排期”，避免继续使用含混的“安排”。
- 若展示 Event 摘要，时间比仅展示标题更有决策价值。
- 空状态应使用对象词：例如“今天没有待办”，不能用覆盖 Task 与 Event 的“没有安排”。
- 页面中的加载状态可从孤立 spinner 升级为保留布局的 skeleton，以减少跳动。
