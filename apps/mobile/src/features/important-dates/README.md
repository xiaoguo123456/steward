# 重要日前端模块

## 职责

本模块负责首页“重要日”场景，包括下一次日期摘要、后续列表、新增／编辑表单、日期选择、年度重复、提醒选项、处理／撤销、删除和详情面板。

## 入口与公开接口

- 路由入口：`features/[slug]`，其中 `slug=important-dates`。
- 公开组件：`ImportantDatesContent`。
- 页面外壳、返回导航和 AI 悬浮入口仍由场景路由统一提供。

## 数据边界

- 列表使用正式 `GET /v1/important-dates` 读模型；新增、编辑、标记处理和删除通过生成 Client 操作 `event_kind=important_date` 的全天 Event。
- `ImportantDateKind` 是页面视图模型；保存时映射到契约中的 `important_date_kind`，不得作为另一套网络 DTO。
- 年度投影、2 月 29 日、时区、剩余天数和组内排序由 Go Domain 负责。客户端只按 `days_until` 把响应分成“即将到来／更多重要日”与“已过期”，保留各组的服务端顺序，不自行重算日期或重排。
- `days_until < 0` 只表示服务端计算出的过期；`important_date_handled_at` 只由明确处理操作写入。已处理条目由服务端从活动读模型排除，客户端不得根据过期自动标记处理。
- 一次性重要日可标记已处理并短时撤销；更新日期会恢复为未处理。删除使用 Event 软删除并在执行前展示明确确认。
- 当前提醒只保存正式 Event 提醒规则，设备推送注册与 Expo Notifications 尚未接入；页面不得暗示系统通知已经送达。

## 日期选择

- 新增表单使用内联的年、月、日三列滚轮，不展示完整月历。
- 年份范围为 1900 年至当前年份之后 100 年；切换年月时自动处理大小月与闰年。

## 禁止依赖

- 不直接依赖后端、数据库或 AI Provider 实现。
- 不手写 Event 网络 DTO、URL 或 Schema，只使用 `@steward/api-client`。
- 不直接访问系统联系人、设备日历或通知权限。
- 不让 AI 或前端绕过用户确认写入正式数据。
