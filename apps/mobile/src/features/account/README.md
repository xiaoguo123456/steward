# 账号与偏好前端

## 页面

- `/me` “我的”：真实的显示名称、生成头像、脱敏手机号、当前已接通设置、App 内法律与支持入口和退出登录；显示名称在当前页底部面板编辑。“专注设置”和“应用锁”不在当前页面展示。
- `/settings/preferences` 时间与作息：周起始日、工作时间、默认提醒时间。
- `/settings/phone` 更换绑定手机号：同时验证当前号与新号。
- `/settings/ai`、`/settings/memories` 见各自实现。

## 约定

- **契约支持什么就显示什么。** 这一页此前整页写死（“张明 /
  zhangming@example.com”），看起来像账号信息、和登录的人无关；
  「周末工作」「默认任务耗时」「通知设置」这类开关契约里没有对应字段，
  拨了什么也不会发生。已经删掉——用户以为设置生效了比没有这个开关更糟。
- 手机号由服务端脱敏后下发（`138****8000`），客户端不还原也不拼接。
- 时区不是展示偏好，是所有日期语义的换算基准。App 登录、启动和回到前台时读取系统时区并通过现有用户资料接口自动同步；失败后保持旧值并在下次前台恢复时重试，不向普通用户展示 IANA 标识。
- 当前头像由显示名称首字生成。照片头像必须等用户头像与受控媒体的长期引用、短期读取 URL 刷新和删除契约完成后再开放；不能把任意远程 URL 或通用媒体短期 URL 存进资料。
- 退出登录先让服务端作废 Refresh Token，再清本地会话与**全部** Query 缓存；
  不清缓存的话下一个账号会先看到上一个人的数据。
  服务端那步失败也照样退出：本地留着用户已经想丢掉的会话更糟。
- 根布局中的用户数据 Provider 必须等会话恢复为 `signed-in` 后才启用查询。
- 原生端会话保存在系统 Secure Store；冷启动和回到前台在 Access Token 即将到期时静默续期。临时断网、超时、限流或 5xx 不得清除会话，只有 Refresh Token 明确无效、账号失效或用户主动退出才回到登录页。
  登录页若提前请求受保护接口，会在 `401 → 清缓存 → 重建查询` 之间形成循环。
- 多个并发请求同时返回 401 时，退出登录只通知和跳转一次；Refresh 请求本身
  失败时直接结束续期，不能再次递归触发 Refresh。
- 法律、信息清单和帮助入口通过 `/public-page` 的唯一受控 WebView 打开当前环境固定公开路径，不把测试域名写死成生产链接，也不传登录 Token。路由只接收稳定页面键，容器只允许同源 `/legal/*` 和 `/support/*`，禁用 JavaScript、存储、文件访问、第三方 Cookie、多窗口和原生桥接；账号删除操作仍回到原生公开路由。
- 账号删除当前只有状态与范围说明。正式 OpenAPI、再次验证和删除状态机未完成前，不显示“提交删除”按钮，也不让静态 H5 表单伪装成已受理。

## 还没有契约

登录设备列表、导出个人数据、最近删除、通知开关、账号删除执行。
做出来之前不在界面上占位；“账号与数据删除”只打开公开说明，并明确展示当前能力状态。

## 更换手机号

`/settings/phone`。**要同时验证旧号与新号**——这是这一版里授权强度最高的操作。

理由：账号就是手机号（登录＝手机号＋验证码）。只验新号的话，
一个被别人拿到的会话就能把号码换成他的，从此永久接管账号，
而真正的机主再也登不进来——他的号码已经不对应任何账号了。
要求旧号的验证码意味着「光有一个会话不够」。

几处不显然的地方：

- 给当前号发码走 `POST /v1/me/phone/code`，**不传手机号**：
  它是脱敏下发的（`138****8000`），客户端本来就没有完整号码，
  而服务端已经知道请求者是谁。让客户端传一遍只会多一个可以被篡改的入口。
- 换绑码与登录码用途分开（`purpose=change_phone`）。
  否则一个骗到登录码的人就能顺手把号码换走。
- 换绑成功后其他设备上的登录失效，当前设备不受影响。
- 换下来的旧号变成空闲号码：再用它登录会创建一个全新的空账号，
  不会碰到原来那个。
