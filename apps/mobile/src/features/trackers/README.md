# 打卡前端

## 页面

- `(tabs)/data` 打卡首页：今日待打卡、我的打卡、最近记录，右上角进入独立管理页。
- `/trackers/manage`（DAT-05）管理打卡项：创建、编辑名称／频率／字段、归档和恢复；字段配置只在这里出现。编辑面板只保留等宽的“保存修改”和“归档”操作，不提供直接删除；归档后 30 天内可恢复。
- `/trackers/new`（DAT-01）创建打卡项：可以让助理描述生成，也可以自己编字段。
- `/trackers/[id]`（DAT-02）打卡项详情：最近值与变化、周／月趋势和记录列表，不展示字段配置。

## 约定

- 内置打卡项（`builtin_key` 非空）只供运动、专注和记账场景使用，不出现在打卡首页与管理页；深链详情仍不显示改字段与删除入口。
  服务端也拦着同样两件事——界面藏起来不算保证，契约边界才是。
- Record 的发生时间用当地写法「2026-08-19 09:30」输入，提交时转 ISO。
  给用户看带 Z 的字符串只会让人算不清自己记的是几点。
- 编辑已有 Record 时，Schema 里已删掉但这条记录里还有值的字段仍然显示，
  否则用户会在不知情的情况下把它们抹掉。
- 字段 `key` 只在新增那一刻定下来，改字段名不跟着改：
  历史 Record 的值是按 key 存的。
- 自定义打卡项支持不定期、每天和每周指定星期；今日是否到期只读取服务端 `due_today`，客户端不按本地日期猜测。

## 不做

- 不在客户端做单位换算，数值原样提交。
- 不本地推断「今天有没有打卡」以外的任何状态；统计与聚合都走服务端。
