# 亲友前端模块

## 职责

本模块负责首页“亲友”分区的开发期视觉样例，用于验证个人关系 CRM 的信息密度、搜索、关系筛选、人物列表和人物详情层级。

## 当前边界

- 只在 `__DEV__` 开发构建中展示固定演示人物；生产构建仍返回不读取资料的准备状态。首页不放置面向研发的预览横幅，非权威边界由构建门禁、文档和测试保证。
- 开发构建可通过 `/relationships-preview` 在未登录模拟器中验收布局；正式构建会立即返回启动页。
- 搜索、筛选和人物详情只操作当前组件内的展示 Fixture，不保存、不上传，也不构成正式人物能力。
- 首页新增入口使用“添加亲友”图标文字按钮，避免与底栏全局 Capture 的圆形加号混淆；当前点击只说明正式接入边界，不伪装为已保存。
- 当前不申请通讯录、相册或通知权限，不读取聊天、通话、邮件或系统联系人。
- 当前不调用 AI，也不提供关系评分、亲密度判断或自动联系建议。

## 正式接入要求

- 先在功能、设计和架构文档中确认引入 `Person` 领域，替换“MVP 不建立人物档案”的旧决策。
- 通过正式 OpenAPI、生成 Client、Go Domain、用户隔离、幂等、来源、删除和保留策略完成跨端闭环。
- 重要日期继续复用 `event_kind=important_date` Event；人物页只建立关系，不复制日期权威状态。
- AI 只能从用户主动提交的内容生成 Person／Relation／Reminder Candidate 或可追溯关系简报，用户确认后再执行正式 Command。
- 保留手动添加、手动关联和手动提醒路径；同名人物、敏感事实和身份无法确定时不得自动关联。

## 禁止依赖

- 不直接依赖后端、数据库、AI Provider 或系统通讯录实现。
- 不把本地 `RelationshipPerson` 展示类型提升为网络 DTO。
- 不根据联系频率对关系打分，不根据照片猜测人物身份。
