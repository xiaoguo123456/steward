# 运动

## 范围

本模块对应功能规格 8.2、产品设计 9.2 与架构设计 3.3.1 的“运动”生活场景入口，
覆盖运动首页、运动准备、运动进行中、运动总结和历史记录。

支持四种模式：户外跑步、健走、骑行和力量训练。两类页面采用不同交互结构，
不把所有运动压缩成同一种记录表单。

## 数据边界

**这一版只测得到时间。** 不请求定位、计步器或后台运动权限，
因此距离、步数、配速、轨迹都测不到。规则是：

- **测不到的量不显示、也不落库。** 曾经这里给每次跑步都写死
  「32 分钟 / 5.24 公里」，计时器还从 32:18 起跳。那些数字进了用户的
  真实记录，事后没人分得清哪条是真跑出来的。
- 距离与步数由用户在总结页自己填，留空就不写这个字段——
  不填不等于 0，编一个数字进去比缺一项糟得多。
- 时长是真的：应用不需要任何权限就能诚实地测量经过的时间。
- 路线图是示意图，带「模拟路线」标记，不声称是你走过的路。
- 运动记录就是内置「运动」Tracker 下的 Record，用户在「打卡」里看到的是
  同一份数据，不存在第二份运动数据。写入走生成的 API Client。
- 真实 GPS 会话、运动状态机与重复检测要等跨端设计完成后再做；
  接入传感器时只要换掉总结页取值的来源，写入路径不用动。

## 页面

| 页面 | 路由 | 说明 |
|---|---|---|
| 运动首页 | `/features/exercise` | 四种运动的直接入口和最近两条运动记录；不承载目标设置 |
| 运动准备 | `/features/exercise/[mode]/prepare` | 目标、播报、定位或训练计划确认 |
| 运动进行中 | `/features/exercise/[mode]/active` | 户外以用时为主数字；力量训练记动作与组数 |
| 运动总结 | `/features/exercise/[mode]/summary` | 真实时长、手填距离与步数、感受选择、保存确认 |
| 历史记录 | `/features/exercise/history` | 按模式筛选并查看历史摘要 |

## 力量训练的动作库

`strength-library.ts` 是平台内容，全部为徒手动作——产品没问过用户家里有什么
器械，凭空假设有哑铃只会让人做不了。

**每个动作都必须写 `mistake`（常见错误）。** 动作要领说怎么做对，常见错误说
哪里会伤到自己，后者更重要：菜谱写错顶多难吃，深蹲膝盖内扣伤的是半月板，
而且不是当场疼，是练几周之后才疼——那时用户根本不会把它和这个 App 联系起来。

其余几条约定：

- **计次与计时分开**（`ExerciseMeasure`）。平板支撑写「3 组 × 10 次」没有意义，
  它按秒算。旧模型只有 `reps`，所以库里根本放不下静态支撑类动作。
- **难度只分入门与进阶两档。** 分更多档需要评估用户的实际水平，而这个产品
  没有任何依据去评估——硬分五档只是给猜测套上精确的外壳。
- **难的动作要给 `easierId`**，做不了时有退路，而不是让人硬撑。
- **组数次数是通用建议，不是个人训练计划**，界面上必须这么说。这和食谱那边
  「不提供诊断、治疗承诺或用药建议」是同一条立场。

训练计划（`strengthPlans`）决定每个目标练哪些动作。之前这四个目标是摆设：
不管选「上肢激活」还是「下肢基础」，练的都是同一套固定动作。

## 图标策略

- 通用操作继续使用项目既有线性图标；运动模式使用 Pictogrammers Material Design Icons 的同一套成熟运动图形。
- 页面只传入 `running`、`walking`、`cycling`、`strength` 语义名称，具体字形、品牌色和光学尺寸由 `components/ui/icon` 统一适配，Feature 不直接导入图标库。
- 四个运动入口均使用深品牌绿图标与相同浅中性底色，不以颜色区分默认选择，也不维护手绘 SVG。

## 视觉约束

- 页面画布、正文、辅助文字、分隔线和浅色功能面直接复用 `theme/tokens.ts`，不再维护偏灰绿的“运动专属”中性色。
- 品牌绿只承担主操作、选中态、进度和运动图标；危险操作使用公共危险色，地图水域与绿地只保留必要的地图语义色。
- 分区标题统一使用首页的 16／23 Semibold 层级；同类记录使用扁平列表和浅分隔线，不叠加独立大卡片。

## 交互组件策略

- 户外运动的目标类型使用 Expo UI `SegmentedControl`，目标数值使用 Expo 官方支持的 `@react-native-community/slider`。滑杆保留逻辑步长，但使用无密集刻度的细轨道与统一圆形滑块，避免大范围目标产生视觉噪声。
- Feature 只使用 `components/ui/selection-controls` 的品牌适配组件，不直接导入 `@expo/ui` 或 `@react-native-community/slider`；品牌色、外观和后续平台差异由适配层统一处理。
- 开始按钮继续复用运动模块统一主按钮，开关使用 React Native 平台 `Switch`，不在页面里重复实现同类基础控件。
