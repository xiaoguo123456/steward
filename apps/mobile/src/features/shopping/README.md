# 购物前端模块

## 职责

本模块负责首页“购物”场景，包括商品新增／编辑、数量／规格填写、购物进度、品类分组、食谱来源标识和已买到收纳。

## 入口与公开接口

- 路由入口：`features/[slug]`，其中 `slug=shopping`。
- 公开组件：`ShoppingContent`，由场景路由传入右上角新增入口的显隐状态。
- 页面外壳、返回导航、右上角“新增商品”和 AI 悬浮入口由场景路由统一编排；新增与编辑共用底部面板。

## 数据边界

- 购物清单复用正式 `list_kind=shopping` 的 TaskList，每件商品是一条 Task；页面只通过生成 Client 读写。
- 首次使用时按需创建唯一活动购物清单，不在用户初始化时预先生成空清单。
- 数量／规格使用 Task 的 `quantity_text`，品类使用服务端确定性返回的 `shopping_category`，备注复用 `description`，食谱来源从正式来源引用映射。
- 商品行左侧勾选只改变购买状态，点击名称与数量区域打开编辑面板，避免完成与编辑动作冲突。
- “从食谱添加”直接进入当天食材确认页，不先经过食谱首页。
- 新增与编辑面板不要求用户维护独立单位或品类；数量和规格使用一个自由文本字段，品类由服务端确定性分类。
- 从食谱生成购物项时必须先经过购物确认流程；页面不复制菜单的食材合并规则。
- `ShoppingListItem` 和 `ShoppingDraft` 是展示／表单模型，不是网络 DTO。

## 禁止依赖

- 不直接依赖后端、数据库或 AI Provider 实现。
- 不手写 TaskList / Task 网络 DTO、URL 或 Schema。
- 不在客户端维护品类关键词规则或食材合并规则。
- 不让 AI 绕过用户确认创建或完成正式 Task。
