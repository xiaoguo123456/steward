# 购物前端模块

## 职责

本模块负责首页“购物”场景的非权威前端原型，包括商品新增／编辑、数量／规格填写、购物进度、品类分组、食谱来源标识和已买到收纳。

## 入口与公开接口

- 路由入口：`features/[slug]`，其中 `slug=shopping`。
- 公开组件：`ShoppingContent`，由场景路由传入右上角新增入口的显隐状态。
- 页面外壳、返回导航、右上角“新增商品”和 AI 悬浮入口由场景路由统一编排；新增与编辑共用底部面板。

## 数据边界

- 当前商品、数量／规格、品类、备注和来源来自本地 Fixture；新增、编辑与勾选只保存在当前组件状态中。
- 商品行左侧勾选只改变购买状态，点击名称与数量区域打开编辑面板，避免完成与编辑动作冲突。
- 新增与编辑面板不要求用户维护独立单位或品类；数量和规格使用一个自由文本字段，品类由本地规则模拟服务端返回结果。
- 正式购物清单继续复用 TaskList / Task；从食谱生成时必须先经过购物确认流程。
- 当前 `ShoppingItem`、品类推断和数量／规格展示不是网络 DTO。正式分类由服务端确定性逻辑或经用户确认的候选结果返回；若需要持久化数量／规格、品类或来源字段，必须先更新跨端契约与测试。

## 禁止依赖

- 不直接依赖后端、数据库或 AI Provider 实现。
- 不手写 TaskList / Task 网络 DTO、URL 或 Schema。
- 不把前端品类推断当作服务端权威分类。
- 不让 AI 绕过用户确认创建或完成正式 Task。
