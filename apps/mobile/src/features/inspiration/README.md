# 灵感页移动端实现

灵感发现页位于首页顶部标签中，负责低压力地重新呈现用户自己的内容并提供通用思考入口，不替代 Today、Daily Brief、Weekly Review 或全局 AI 助手。

当前首版只读取正式 Notes API：从已沉淀至少 7 天、未删除的笔记中按用户当地日期稳定选择一条“重新遇见”，每天最多一条。页面同时展示一个主问题、三个其他方向和存在时的真实笔记，通过白底、字号与分隔线组织，不放聊天输入框。通用问题不声称来自用户资料；客户端不做语义推断，不伪造关联，也不读取相册、位置、音乐或心情数据。

视觉层级采用编辑式三段结构：当天主问题以短中性规则线、主题标签和大号正文成为唯一首屏焦点；三个其他方向降为“主题／问题”两列目录；真实旧笔记再以来源标签、加强标题、疏朗摘要和两端文字动作形成第二阅读重点。页面不依靠彩色大卡片、装饰图标、渐变或阴影制造“灵感感”。

“开始聊聊”“打开原文”和“继续想想”保持纯文字层级，但复用公共紧凑按钮的 44dp 热区、字号与按压态；可继续思考的动作使用全局品牌绿，中性查看动作使用次级文字，不另建灵感蓝按钮体系。

用户点击问题或“继续想想”后，一次性草稿 Store 把开场问题、来源标签和首个 Turn 上下文交给既有 `/ai` 路由；该路由以全屏方式复用正式 Assistant。打开阶段不会自动发送或创建 Thread，首次回复才创建独立会话。完成一轮回复后，“整理成笔记”进入统一 Capture Confirmation，“生成待办建议”进入 Action Proposal 确认；客户端不会直接写入任务、项目或笔记。后续正式的“发现关联”和“换个角度”必须先增加 `inspiration_card_batch@v1` AI 契约、OpenAPI、服务端来源校验、反馈与删除闭环，再接入移动端。
