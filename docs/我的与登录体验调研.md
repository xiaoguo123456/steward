# “我的”与登录体验调研

## 0. 文档信息

| 项目 | 内容 |
|---|---|
| 调研范围 | 移动端“我的”、资料编辑、账号入口与手机号登录 |
| 目标平台 | Expo SDK 57、iOS、Android，中国大陆手机号 |
| 调研日期 | 2026-08-28 |
| 结论状态 | 已收敛并进入实现 |

本文记录本轮产品决策的证据与边界。产品可见行为仍以《功能规格说明》和《产品设计说明》为准，架构与契约边界仍以《整体架构设计》为准。

## 1. 现状结论

- `/me` 与 `/settings` 重复展示同一组设置，用户需要先理解“账户与设置”和“全部设置”的差别，实际没有新增信息。
- 资料页只有显示名称与时区。显示名称是高频、低风险的短编辑；IANA 时区是日期计算基准，不是普通用户需要维护的展示偏好。
- `avatar_url` 虽存在于用户 DTO，但当前没有“用户头像引用受控媒体”的正式契约。通用媒体接口返回的是短期只读 URL，不能把它长期保存为头像；直接允许客户端填写任意远程 URL 也无法校验所有权、删除和生命周期。
- “账号与登录”已有脱敏手机号与双验证码换绑，不是完全空壳；但单独页面只承载手机号、时区和退出登录，其中时区不应展示，因此剩余内容适合直接收纳在“我的”。
- 登录只有手机号加短信验证码。测试环境可以由后端返回固定 `dev_code` 自动填入，生产环境不会回传验证码。

## 2. 资料编辑形态比较

| 方案 | 优点 | 主要问题 | 结论 |
|---|---|---|---|
| 独立页面 | 可容纳多字段、裁剪头像和复杂校验；系统返回语义稳定 | 当前只有名字和生成头像，新增导航层级明显重于任务本身 | 不采用；将来若增加头像裁剪、个人简介等复杂字段再评估 |
| 资料区内联编辑 | 上下文最直接，不产生遮罩 | 键盘出现后会推动“我的”整页；编辑态与浏览态容易混杂，取消和错误反馈也会挤压一级信息架构 | 不采用当前实现；适合单个、即时保存的小字段 |
| 底部面板 | 保留“我的”上下文，适合短而聚焦的编辑；可提供明确取消、保存、加载与错误状态 | 仍是模态任务，需要可发现的关闭方式，并防止重复提交 | 采用 |
| 中央弹窗 | 实现简单，适合高风险确认 | 软键盘和动态字号下空间局促；名字编辑不是需要打断用户的高风险决定 | 仅用于退出登录等确认，不用于资料表单 |

Apple Human Interface Guidelines 将 Sheet 定义为与当前上下文紧密相关、范围明确的短任务，并要求提供清晰的关闭和完成操作；同时提醒只在有明确收益时使用模态。本次编辑只有一个文本字段，符合短任务而不值得新增页面：

- [Apple：Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)
- [Apple：Modality](https://developer.apple.com/design/human-interface-guidelines/modality)

最终交互：点击资料栏打开“编辑资料”底部面板；头像使用显示名称首字即时预览；取消不写入，保存期间禁用关闭与重复提交，失败保留输入并就地提示。照片头像不做不可持久化的假入口。

## 3. “我的”信息架构

一级页标题统一为“我的”，内容按使用频率和风险排序：

1. 资料栏：头像、显示名称、脱敏手机号；点击打开底部编辑面板。
2. 偏好：最近输入、时间与作息、AI 设置、长期记忆；番茄钟从首页场景入口进入。
3. 账号：绑定手机号，点击进入真实的双验证码换绑流程。
4. 危险操作：退出登录，置于页面底部，二次确认，提交期间防重复。

不再保留“全部设置”和“账号与登录”中转页。登录设备、第三方账号绑定、安全中心、数据导出等没有正式契约的能力不占位。

## 4. 时区决策

时区影响 Today、日期归属、提醒和相对时间解析，但不应要求普通用户理解或选择 IANA 标识：

- 登录时继续把系统当前 IANA 时区传给服务端，作为新账号初始值。
- 已登录 App 启动和回到前台时，对比系统时区与用户资料；不同则复用 `PATCH /v1/me` 自动同步，然后刷新依赖日期语义的查询。
- 同步失败不阻塞用户，保持服务端旧值并在下次启动或回到前台重试；不弹出一个用户无法解决的技术错误。
- 跨时区事件仍在具体事件详情显示事件时区和本地时间。只有未来出现“固定常驻时区”“旅行时不跟随设备”等明确高级场景时，才增加高级设置。

## 5. 本机号码一键登录调研

### 5.1 能力不是“读取一下 SIM 号码”

真正的一键登录是运营商网关认证：客户端 SDK 展示脱敏号码与运营商授权页、取得一次性 Token；业务服务端再用 Token 调号码认证 OpenAPI 取回完整号码，最后由自己的 Auth Domain 创建用户与会话。Token 具有短有效期且只能使用一次。阿里云官方同时明确区分：Phone Number Hint 或本机号码校验不能代替一键登录。

- [阿里云号码认证：集成概览](https://help.aliyun.com/zh/pnvs/developer-reference/sdk-integration-overview/)
- [阿里云号码认证：服务端集成](https://help.aliyun.com/zh/pnvs/developer-reference/number-authentication-server-integration)
- [阿里云号码认证：产品能力与三网覆盖](https://help.aliyun.com/zh/pnvs/product-overview/what-is-the-number-certification-services)
- [中国移动：号码认证能力](https://dev.10086.cn/numIdentific)

Android 的 Phone Number Hint 只是在系统授权界面让用户选择 SIM 号码，官方明确说明它“不直接绑定登录或注册流程”；号码仍需短信验证码或其他正式认证。它可作为减少输入的增强，不能命名为“一键登录”：

- [Android Developers：Phone Number Hint](https://developer.android.com/identity/phone-number-hint)
- [Android Developers：最小化权限请求](https://developer.android.com/privacy-and-security/minimize-permission-requests)

### 5.2 当前仓库为什么不能直接展示按钮

- 没有 iOS/Android 号码认证原生 SDK、Expo Module 或 Config Plugin。阿里云号码认证方案管理文档明确写明暂不支持 Expo，需要自行研发接入；新增原生能力后还必须重建开发预览包。
- 没有客户端认证方案、包名/签名/Bundle ID 对应配置和运营商授权页文案。
- OpenAPI 只有短信 `requestPhoneCode/login`，没有“提交运营商 Token、服务端换号并签发 Steward Token”的契约、稳定错误码或幂等规则。
- 测试环境只有固定短信码，没有三网真实 SIM、蜂窝网络、双卡、无 SIM、Wi-Fi/蜂窝切换、用户取消、Token 超时和供应商故障的测试矩阵。
- 引入第三方 SDK 后需要更新应用内隐私政策、App Store 隐私申报和 Android 数据安全申报。手机号属于联系信息，且第三方 SDK 的收集也必须纳入披露。中国《个人信息保护法》第十七条要求处理前以显著、清晰方式告知处理者、目的、方式、种类和保存期限。

### 5.3 分阶段方案

**阶段 A（本轮）**

- 只展示确定可用的“手机号 + 验证码”登录。
- iOS 使用系统 `telephoneNumber/oneTimeCode` 语义，Android 使用 `tel/sms-otp` Autofill 语义，减少手输；这只是自动填充，不改变认证强度。
- 保留手机号与已输入内容，发送失败、验证码错误、过期、限流和网络失败均可恢复；发送和登录期间禁止重复提交。
- 测试环境继续使用后端 `dev_code`，生产环境只提示查收短信。

**阶段 B（接入前置）**

- 产品确定供应商、三网范围、费用、SLA、隐私文案和短信降级口径。
- 新增 Expo 原生模块/配置插件以及 iOS、Android 真机开发包。
- OpenAPI 新增一次性运营商 Token 登录接口、能力发现字段、稳定错误码与 Fixture；后端 Adapter 调供应商 OpenAPI，Auth Domain 仍负责账号、Session、限流、幂等和用户隔离。
- 客户端只有在 SDK 环境检测和服务端 capability 同时可用时才显示一键登录；否则直接显示短信登录，不先闪现再消失。

**阶段 C（灰度）**

- 覆盖移动、联通、电信，iOS/Android，单卡/双卡、无 SIM、Wi-Fi、蜂窝网络、弱网、用户拒绝、Token 过期、服务端换号失败和短信降级。
- 一键登录授权页明确运营商、脱敏手机号、服务协议与隐私政策；用户取消立即回到短信路径，不循环弹出。
- 以成功率、降级率、耗时和隐私投诉为灰度门槛；未达到门槛时关闭 capability，不影响短信登录。

## 6. 无障碍与验收依据

- 所有核心操作保持至少 44×44 pt/dp；Android 官方建议交互焦点区域至少 48×48 dp，本次列表行和按钮按更高的平台建议实现。
- 输入、错误与成功提示提供读屏名称和 live region；不只依赖颜色表达状态。
- 文本容器不锁死高度，支持换行和系统动态字号。Apple 建议支持至少 200% 放大并在最大字号检查遮挡和截断。
