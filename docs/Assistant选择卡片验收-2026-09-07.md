# Assistant 选择卡片验收（2026-09-07）

## 问题与修复

原澄清选项复用了没有背景和边框的气泡容器，禁用后又整体降低透明度，导致选项看起来像灰色正文。现在使用独立的原生卡片，整张可点击，标题与日期／状态分行，显示序号和箭头。提交时禁用，回答后标记已选项或本轮已结束，保留文字可读性。历史选择仅根据紧接着的用户原文或编号做视觉回显，服务端仍校验问题与选项有效性。

原消息下的建议仅取自全局待确认列表，已处理建议被过滤后，出现只有“请查看卡片”的提示。现在按消息引用的 proposal_ids 补读正式建议接口，复用现有卡片显示真实状态；读取失败显示重试入口，404 显示不可用。已执行建议没有再次确认按钮。

载体决策：React Native。复用生成的 API Client、网络校验器和已有建议查询接口，无 API 字段、错误码、数据库、Go Domain、Prompt、模型、AI Schema、原生权限、H5 或第三方清单变更，因此不需要重新生成契约或执行模型 Eval。

## 验证

Android 模拟器使用实际 Expo 开发客户端，挂载此次生产组件，通过临时合成数据入口进行原生点击验收。建议查询走实际生成 Client 和响应校验器，网络响应由内存 Fixture 提供。本轮没有连接生产账号，没有执行真实任务修改，也不属于生产对话端到端验收。临时入口已删除，正式 Expo Router 入口已恢复。

- 选择第一项：出现绿色边框、勾选和“已选”，两张卡片均不可重复点击。
- 本轮结束：出现“本轮选择已结束”，两张卡片均禁用。
- 已执行建议：显示修改前后日期和“已执行”，没有“确认执行”按钮。
- 模拟查询失败：显示读取失败与“重新加载”；恢复响应后点击实际重试按钮，重新显示已执行建议。
- 长标题：正常换行，元信息与箭头不重叠。
- 系统字号 200%：普通标题、日期与状态正常显示，验收后恢复原字号。
- 移动端 Lint、TypeScript 类型检查、完整测试均通过；增加历史选择识别与展示分段测试，并将已有交互契约测试加入默认 Assistant 测试命令。
