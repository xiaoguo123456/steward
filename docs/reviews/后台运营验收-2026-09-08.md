# 任务详情精简与后台运营验收

## 结论

后台已有基础运营功能，但检查前不具备可靠上线条件。最直接的阻塞是测试、生产
专属后台账号缺少已有统计表的 SELECT 权限：实测读取 admin.user_index 都返回
permission denied。以下修复已在代码与本机隔离环境完成，并于 2026-09-08 发布到测试和生产。

代码 `225401b7017e` 已合并主分支。测试工作流 `34185719602`、生产工作流

## 本次修复

1. 原生任务详情移除固定的“所属项目”和“加入日期”两行。有项目时标题下显示
   可打开项目的小标签；按实际项目 ID 查询，避免一次只拉前 100 个项目导致归属显示错误。
   关注日期仍保存在领域数据中，已有编辑和计划操作保留。
2. 新增迁移 00058，只向当前环境后台角色授予 user_index、user_daily_usage、
   aggregation_runs 三张脱敏读模型表的 SELECT。无 BYPASSRLS 或正文权限扩张。
   发布流程增加生产账号命名的独立权限回归；默认权限不追溯旧表的缺陷不会再被
   本地通用 steward_admin 角色掩盖。
3. 后台会话失效由正式 Client 统一通知 SessionProvider，清除状态、CSRF 与缓存，
   覆盖直接调用的管理写请求；旧请求不得清掉已经建立的新会话。
4. 管理确认期间禁用表单与取消，同步阻止重复提交。网络结果未知时相同请求保留
   幂等键；版本冲突后刷新当前用户并由管理员重新确认。
5. 详情接口补返已有预算，页面显示并回填限额、注册时间、名称和最近活跃；
   管理记录与处理记录支持翻页，用户列表补初始化筛选、名称、最近错误和重置。
6. 总览、使用分析和成本增加报表时区日期范围；历史 WAU／MAU 加上窗口上界。
   新用户漏斗限定同一注册人群，初始化采用该人群当前状态，业务阶段限定期间活跃，
   不混用全量初始化数或全站 MAU。
7. 聚合按报表时区重算昨天和今天，补上午夜前最后一小时；单用户聚合失败时整轮
   明确失败并跳过清扫，不能报告数据已完整更新。
8. 页面错误提供重试；失败统计分区显示不可用；成本缺价提示不再把用户日报条数
   误称为天数。跨用户成本页暂不显示被 Assistant 轮次代替的“调用”列。

## 尚不完整的能力

- 全站 AI 调用量、成功率、延迟分位数、按模型／Provider 分组未完整聚合；部分后台
  API 仍有占位计数，不能用于正式账单或服务质量判断。单用户成本已有正式查询。
- 价格版本页面目前只读，没有新增／停用表单；补价后的历史重算需要独立验收。
- Provider 页主要列出价格表中的服务商，不能代替真实服务健康监控；失败 Operation
  总数使用丢弃队列近似，也不能作为精确故障统计。
- 注册时间、最近活跃、是否使用 AI、失败处理记录等高级用户筛选未齐备；运行中心
  缺少完整的处理记录查询界面。现有单用户详情可查看状态和错误码。
- 已支持数据库维护多个手机号管理员，详见《后台手机号认证验收-2026-09-08》；
  尚没有多人分权、工单反馈、版本分布、崩溃监控和留存分析。
  这些属于后续运营规模和监控建设，不能用静态页面冒充已实现。
- 用户管理状态列表采用小时聚合快照，详情和写操作用实时状态；刚处置的用户应以
  详情为准。长时间停机的历史日报补算、严格时序漏斗和更多业务活跃事件仍需完善。
- 本轮只进行了线上只读检查，没有登录生产后台执行用户处置；发布后必须验收
  正式管理员登录、真实用户查询和统计读取，并按专用测试账号完成管理操作闭环。
