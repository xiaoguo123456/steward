# 登录态续期排查与修复

## 已确认的问题

测试环境使用既有验收账号通过正式接口登录成功后，第一次刷新立即返回
HTTP 401 / REFRESH_TOKEN_INVALID。Access Token 有效期为两小时，Refresh Token
有效期为三十天；后者并未过期。测试、生产的只读结构检查均确认迁移版本 56、
函数属主非超级用户且无 BYPASSRLS、auth_refresh_tokens 强制 RLS。

00050 的 auth_rotate_refresh_token 使用 SELECT FOR UPDATE，同时受 SELECT
和 UPDATE 行级策略约束。00032 只给匿名 SECURITY DEFINER 路径提供最小 SELECT
能力，未设置用户上下文时锁定查询看不到会话，误报刷新凭证无效。
原生客户端已有 SecureStore 持久化与自动续期；上述服务端故障足以导致续期时退出。
它不能单独证明“登录后马上重开”的全部场景均由该原因导致。

## 修复

- 新增向前迁移 00057：按凭证哈希定位所属账号，在该账号的既有 RLS 范围内锁定、
  重验和轮换；函数返回前恢复原调用者上下文。不关闭 RLS，不增加全表写绕过权限。
- 保留无效、过期、撤销与并发重放拒绝，以及旧令牌重放撤销整族行为。
- 补充连续轮换、原调用者身份恢复与跨用户隔离测试。
- 测试和生产发布流程新增独立认证数据库，迁移角色与函数属主均无超级用户和
  BYPASSRLS 权限，避免常规超级用户创建函数的测试掩盖线上缺陷。
- OpenAPI、生成 Client、客户端持久化方式、AI 契约和隐私处理范围均未改变；
  不需要重新安装 APK，服务端部署后生效。

- 本地专用 PostgreSQL 18 隔离库，以受限角色运行完整 1—56 迁移：
  既有 Refresh 并发测试失败，成功 0 次、无效 2 次，复现线上问题。
- 同一库升级 57 后，认证模块 go test -race 全部通过，包括连续轮换、账号隔离、
  并发重放和手机号换绑会话保护。
- 根 make check 通过。全量模块使用单独新建的标准回归库，认证模块额外使用
  上述受限属主数据库。
- sqlc 生成无漂移；actionlint 通过；gofmt、go vet 已随检查通过。
- golangci-lint 全库有 28 项已有告警；以变更前 HEAD 为基线检查新增问题为 0。
- 当前原生模拟器无法通过可用的原生 UI 控制入口接入；已安装发布测试 APK，
  但没有完成杀进程重开、断网重开、设备重启或生产账号登录实测，不声称原生闭环通过。
- 测试账号使用过程中不输出或保存令牌、验证码；线上结构检查不读取用户会话内容。

## 独立待办

将全部模块改用受限函数属主执行时，还发现既有账号删除集成测试无法取得应删除
的对象存储媒体。该问题与本次登录续期无关，未通过扩大数据库权限掩盖，需独立
排查 retention 的 SECURITY DEFINER / FORCE RLS 路径。当前新增发布门禁专门覆盖认证。
