# 后台手机号认证与发布验收

## 功能与载体

管理员用数据库白名单中的手机号登录，首次短信验证后必须设置密码，以后支持密码／
验证码登录以及验证码重设密码。载体为独立内部 Web，不嵌入 App，不新增原生权限或
第三方 SDK；复用现有阿里云短信服务，登录页说明用途、发码前主动确认并链接隐私政策。
App 登录凭据不能用于后台。身份验证和授权按用户明确指定的确定性流程实现，不交给 AI。

## 页面与数据边界

默认验证码登录，密码登录平级切换，忘记密码进入独立表单。首次验证后递进展示密码及
确认密码，未设密不签发会话。密码要求 12–128 字符，可使用密码管理器。提交期间禁用
重复操作，错误保留输入，切换号码或用途会清掉旧挑战。重设后清除密码输入并回到登录。

`admin.accounts` 独立保存管理员名单与 Argon2id 散列；`admin.phone_challenges`
保存专用挑战与验证码 HMAC；`admin.sessions` 关联稳定管理员 ID 和凭据版本。
账号行锁串行化发码、消费、设密与重设；错误验证码次数必须提交，不能随业务拒绝回滚。
验证码 5 分钟有效、最多尝试 5 次，发码间隔 60 秒、每小时 5 条、每日 10 条，
另按来源和账号原子限流。生产禁止固定码，后台任何环境的接口均不返回验证码。
后续发码清理超过 7 天的挑战。登录和重设用途隔离，不复用 App 验证码。

后台账号仅能读取名单和更新密码相关列，不能新增管理员、改手机号或启停账号。
停用后每次会话验证均拒绝；密码重设原子递增凭据版本并撤销所有旧会话。
CSRF 从独立密钥和会话 ID 派生，刷新后可恢复。审计仅记录稳定身份和动作，无完整号码或凭据。

## 名单运维与发布

使用对应环境迁移／运维连接，在事务中向 `admin.accounts` 插入唯一稳定 `id`、
已授权 `phone`、`enabled=true`、`password_hash=NULL`。新管理员自行验证并设密，
不设置默认共享密码，不把生产号码写入迁移或仓库。停用时设置 `enabled=false`，
递增 `credential_version` 并撤销该 ID 的全部会话，避免以后重新启用时恢复旧会话。

Admin API、数据库和网页按同一 SHA 发布。迁移 00059 撤销旧用户名会话，
不再接受 `STEWARD_ADMIN_USERNAME`、`STEWARD_ADMIN_PASSWORD_HASH` 登录。
短信复用 `STEWARD_SMS_PROVIDER` 与 `STEWARD_ALIYUN_SMS_*`。Admin OpenAPI 同步生成
Go strict handler、TypeScript Client 与 Zod；原生 App 无对应接口适配或安装包变化。

## 验证

- Go 并发集成测试覆盖首次设密、密码登录、错误次数、过期、单次消费、用途隔离、
  重设与旧会话撤销、停用、未授权号码、运行账号不能维护名单，以及 Origin／CSRF。
- 真浏览器连接本地隔离库，虚构号码已走通首次验证设密、登录、刷新后退出、
  验证码重设密码、新密码重新登录。
- 前端及契约 Fixture 覆盖渐进设密、密码不一致、找回用途和换号后挑战失效。
- 根 `make check`、后台类型检查及生产构建通过，前端共 17 项测试通过；后台全部模块
  执行 `go test -race -count=1`，认证变更后再次复核通过；新增 golangci-lint 问题为 0。
- Admin OpenAPI、Go DTO／strict handler、sqlc、TypeScript 与 Zod 已重新生成；
  发布门禁额外验证环境专属后台角色不能添加或启停管理员。
