# 记账媒体识别排查与修复

日期：2026-09-08。仅使用虚构小票和合成语音，不记录原始媒体、凭据或真实用户正文。

## 问题与修复

1. 拍照记账复用通用任务输入提示，并自动弹键盘遮挡图片来源入口。改为记账示例、选图后的可选备注提示，进入时不自动弹键盘。保持原生流程，无新增权限、SDK、H5 或个人信息用途。
2. 纯语音从记账入口提交也要求“识别票据”。改为按本次输入生成待确认记账记录。
3. 真实图片和语音均可能输出中文 `direction`，而旧月报只统计 `income`／`expense`，造成漏算。Trackers Domain 在手工及 AI 创建、更新时统一处理明确的中文收支值；未知方向和非正金额拒绝。移动端兼容历史中文值，防止既有记录漏算。
4. 小票明确的交易时间被遗漏，最终使用识别时刻。`capture-parse@v9` 补齐 timestamp 示例，并约束交易时间、实付金额及收支机器值。沿用 v6 Schema、RecordValue、timestamp 和已有错误码，没有新增网络字段或数据库列，无需迁移或重新定义 DTO。

## 验证

- 根 `make check` 通过；Trackers／Captures／OpenAI 竞争检测通过。
- 新增旧中文收支月报回归、内置账本归一化／未知方向／非正金额／自定义字段隔离测试。
- `TestLiveLedgerMedia` 通过现有真实模型先 OCR／ASR 再解析：38 元原价、10 元优惠的小票识别实付 28 元并保留 12:30 交易时间；语音交通支出 35.6 元、兼职收入 128 元均方向正确。逐样本识别加解析耗时约 4.46／3.16／2.76 秒，小样本不代表生产 SLA。
- 第一批系统合成音频在沙箱中生成空 WAV，服务端正确拒绝。改为有效 16 kHz 单声道音频后真实转写成功；不能将素材错误算作 App 录音故障。
- 测试服务器真实 HTTP 端到端通过三类样本：上传、OCR／ASR、候选、确认入账、读取校验。分别约 5.70／4.70／4.62 秒；确认前没有新账单，同一幂等键重复确认没有重复记录。账单与媒体已按本次创建 ID 清理。
- 一次语音候选缺分类时已正确携带 `missing_fields`，直接跳过编辑确认会被拒绝；这是既有门禁有效，不是错误入账。
- 手机尺寸页面已实测小号“＋ 新建”、分区左对齐、移除管家卡片、模板预填及自定义清空。
- 原生相册成功选择虚构小票并上传，但一次模型输出两次 Schema 校验失败。日志只给出候选 `$ref` 包装层，不能定位最初具体错误；不能据此推定是上传故障。补丁递归提取叶子约束，仅暴露可信 Schema 路径和期望约束，保留一次重试上限及失败不入账的边界。增加嵌套缺失／类型／枚举／未知字段及正文不泄露回归测试；独立已迁移数据库中的 AI 评测通过。
