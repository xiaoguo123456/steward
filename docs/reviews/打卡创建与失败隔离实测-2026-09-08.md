# 打卡创建与失败隔离实测

后续状态：本报告记录的普通聊天完成误报已继续排查并修复，详见[聊天完成误报链路排查与修复](聊天完成误报链路排查与修复-2026-09-08.md)。下文保留当时的原始观测。

日期：2026-09-08。环境：独立本地数据库、本地 API／Worker、Expo Web 页面；真实模型为仓库配置的 qwen3.8-flash。所有输入均为虚构测试样本，没有修改生产账号数据。

## 已发现并修复

1. 管家只要持有 Capture Session 就锁住输入，即使它已失败。现按当前 Capture ID 的阶段决定是否阻塞；失败、读取异常和终态释放输入，待处理项可“先放一放，继续聊”。暂放只影响当前 App 会话，不丢弃服务端数据，可从最近输入恢复。
2. AI 创建打卡没有传递频率。新增版本化的 `tracker_schedule`，贯通 AI Schema、中立类型、公开 OpenAPI、生成 Client、确认编辑器和 Tracker Command；沿用已有数据库频率列。每天和每周指定星期可保留，未提供星期先澄清。
3. 真实页面中，饮水字段已完整，确认检查仍提示“字段结构缺失”。原因是结构必填检查复用了文本冲突选项的允许字段集合，集合没有 `fields`。现将结构存在性与文本覆盖权限分开，正式跨端 Fixture 已加入确认可用性测试。
4. 通用 Record 把 0 和负数当作未填写。现只检查是否为有限数值，具体数值范围交给对应领域校验，不让前端通用逻辑覆盖业务规则。
5. 专用打卡描述页误露出“新建任务”，失败后页头仍写“正在处理”。现改为“自己填写”返回打卡表单，页头用“这次输入”，详细状态由内容区显示。确认卡名称统一为“打卡”。
6. Web 开发构建无法解析 Babel 的运行库 helper。移动端声明已有锁定版本的 `@babel/runtime` 直接依赖后，构建及页面加载恢复。

## 打卡入口

- 首页移除“记一件事”“自己新建”，保留一个明显的“新建打卡”按钮。
- 空页和新建页提供体重、饮水、睡眠、阅读四个模板。
- 模板仅预填名称、字段、单位及每天频率，允许改动；用户保存前不创建打卡或记录，不向账号自动灌入默认项目。
- 新建页保留自定义和“让管家帮我建”。载体继续为 React Native 核心功能，完整体验需新版原生包，无新增 H5、权限或第三方 Provider。

## 真实模型样本

`TestLiveCaptureCheckins` 九类样本全部通过：

| 样本 | 结果 | 模型耗时 |
| --- | --- | --- |
| 只创建饮水打卡 | 一个 Tracker，无空 Record | 2.06 秒 |
| 饮水 500 毫升 | Tracker 与 Record 正确关联 | 2.84 秒 |
| 睡眠 7.5 小时 | 数值及关联正确 | 3.12 秒 |
| 阅读 30 分钟 | 数值及关联正确 | 2.97 秒 |
| 每天阅读，分钟数与页数 | 两字段与每日频率保留 | 2.34 秒 |
| 每周一三五阅读 | 每周频率及星期保留 | 2.14 秒 |
| 两个同名饮水项 | 先澄清，不猜测目标 | 1.63 秒 |
| 无意义输入 | 无候选，先澄清 | 1.97 秒 |
| 每周但没有星期 | 阻塞本次确认并追问 | 5.69 秒 |

这是小样本模型调用耗时，不是生产端到端延迟或质量保证。

新增 Prompt 后又回归六个原体重场景，全部通过；其中“不能配到专注”耗时 15.29 秒，其余约 1.5～4.6 秒，仍存在模型响应长尾，不能据此承诺每次 2～3 秒完成。

## 点击与故障注入验收

1. 空打卡页显示四模板和新建按钮，没有旧入口。点击阅读后预填阅读时长、分钟、每天；保存后列表出现一项阅读，尚无 Record。
2. 从“让管家帮我建”提交饮水描述，进入 Capture 确认流程。
3. 将这条虚构 Capture 和 Operation 注入失败：错误提示出现，输入框恢复可用，后续消息能实际提交。测试用 fake Assistant 不提供回复时也正常失败收尾；切换真实模型后下一条消息成功返回。
4. 点击“先放一放”后旧 Capture 卡片从当前会话隐藏，可以继续对话，原始输入保留。
5. 同账号再次通过真实模型创建每日饮水打卡，点击确认卡“保存”成功；数据库核验 `confirmed`、一个饮水字段及 `schedule.frequency=daily`。前一条失败没有阻塞这一条正式保存。
6. 数据库集成测试覆盖 Provider 失败、候选字段损坏后同用户继续成功；旧失败 Job 迟到重复投递不会再次调用模型。确认事务测试同时核验每周一三五频率和同批 Record 的幂等保存。
