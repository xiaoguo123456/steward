本页是仓库唯一的全局实现进度表。功能规格中的“必须／应该”表示目标规则，不等于已经实现；架构文档中的目标目录和技术边界也不等于依赖已经安装。根 README、App README 和模块 README 不再分别维护一份全量进度。

状态定义：

- **正式闭环**：已经使用正式契约和服务端权威状态，移动端存在可用入口；不代表已经通过应用商店发布验收。
- **部分接入**：主要数据已进入正式领域，但仍有本地会话、模拟识别、未接系统能力或缺少独立入口。
- **前端原型**：只用于验证交互或视觉，不写正式业务数据。
- **准备状态**：只有占位或边界说明，没有对应正式功能。
- **服务端已具备**：契约和后端存在，但当前移动端没有独立入口或没有完整用户闭环。

## 总体结论

仓库已经具备 Expo 移动端、生成式 TypeScript Client、Go 模块化单体、PostgreSQL／River、公共与管理 OpenAPI、AI JSON Schema 和管理后台。核心 Task／Event／Project／Note／Tracker／Record、Capture、Assistant、长期记忆等链路已进入正式契约。

“全部生活场景都已接真实 API”仍不准确。时光已经接入正式媒体与照片时光 API，亲友已接入正式 People API 及人物关联，音乐已退出当前首页信息架构；专注和运动仍各自保留明确的本地会话或设备边界。记账已移除客户端模拟识别并统一进入正式 Capture／Record。公开法律与支持页面的版本 1.0 正式稿、数据保留口径、账号删除技术闭环和发布门禁已完成，公司授权确认已于 2026-09-02 完成；阿里云百炼真实模型已通过协议级回归，生产端到端 AI 验收和应用商店资料仍是发布阻塞项。

## 用户侧能力

### 核心管理与 AI

| 能力 | 状态 | 代码核对结果 |
|---|---|---|
| 手机号登录、刷新、退出、资料与偏好、手机号换绑 | 正式闭环 | Public OpenAPI、Auth／Users 模块和移动端页面均存在；手机号只以服务端脱敏结果展示；登录页按“手机号与协议确认 → 验证码与登录”两阶段渐进展示，并区分网络、限流与短信服务错误；首次发送验证码前要求用户主动勾选协议并可打开环境化 H5 链接 |
| Today、TaskList、Task、日历／Event、Project、Note | 正式闭环 | 移动端使用生成 Client；Task 与普通 Event 具备详情、全字段编辑和删除路径，Calendar／Project 可进入 Event；Task 拆分使用可删选、可改标题的批量 Proposal，智能排期复用 `task_update` Proposal，均在确认后才由 Go Domain 写入；时间、状态、Today 收录和排序由 Go Domain／查询决定 |
| Tracker／Record | 正式闭环 | 自定义 Tracker、记录、统计和归档恢复已接正式接口；内置 Tracker 不进入通用打卡首页 |
| Capture 与媒体上传 | 正式闭环（设备离线队列） | 文字、音频、图片组合进入 Capture；AI 只生成 Candidate；确认页编辑后由 Go 重新校验。原生端使用按账号分库的 SQLCipher 保存草稿与队列，媒体先复制到应用持久目录；断网发送进入 `waiting_for_network`，恢复网络先询问，已确认队列以稳定幂等键、同一 `media_id` 和新签名授权续传。退出登录可选择保留或删除当前账号草稿 |
| AI Provider 运行门禁 | 正式闭环 | `fake` 只允许开发和测试环境显式使用；生产环境配置为 `fake` 会拒绝启动。真实 Provider 不可用或结构修复失败时进入可重试错误，不静默降级到规则候选 |
| Assistant 对话、建议确认与长期记忆 | 正式闭环 | Thread／Turn／SSE、Proposal 确认、Memory 设置页均已接正式接口；模型没有直接写库路径 |
| Weekly Review | 正式闭环 | 指标由服务端确定性计算；AI 小结可选且要求来源，个人补充保存为正式 Note |
| 全局搜索、操作记录与撤销 | 服务端已具备 | OpenAPI 与 Go 聚合／Activity 模块存在；当前移动端路由中没有独立全局搜索页或活动历史页 |
| 设备推送通知 | 尚未形成正式闭环 | 服务端存在待提醒读模型，但移动端未安装或接入 Expo Notifications，也没有设备注册与通知设置契约 |

### 首页分区与生活场景

| 场景 | 状态 | 正式与本地边界 |
|---|---|---|
| 今天 | 正式闭环 | 使用 `/v1/today` 与待提醒读模型；客户端不重排权威 Today 结果，首页只把 Task 作为“今天要做”主区，Event 进入日历或到点提醒，不再拼装“今日安排”摘要 |
| 心情日记 | 正式闭环（AI 正文受门禁） | 日记、日历、搜索、确定性统计、保存后单篇追问及周／月逐篇选择回望已接正式 API；草稿使用本机安全存储。真实正文仅在全局开关、单独同意、逐篇排除和部署级敏感 Provider 门禁全部通过后发送，结果不自动写入日记或 Memory |
| 时光 | 正式闭环（AI 与离线恢复受门禁） | 图片经正式媒体授权上传，时间线、月历、详情、幂等发布和整段删除使用 Memory Moments API；发布页只保留选图和可选描述，发布日期由服务端按账号时区生成，发布后不可编辑且不再装载 Fixture。第三方图片 AI 未完成单独同意、清单、Schema 与 Eval，当前不调用 Provider；发布页进程恢复和独立持久上传队列尚未实现 |
| 亲友 | 正式闭环 | 使用正式 People、Person Event 与 Person Task OpenAPI、生成 Client、Go Domain 和用户隔离查询；只保存用户主动录入的人物及关联，不读取系统通讯录，不装载 Fixture，也不让 AI 直接写入 |
| 音乐 | 未进入当前范围 | 已由“亲友”替换首页入口；不播放、不生成音频，也没有正式领域或契约 |
| 食谱 | 正式闭环 | 菜谱、饮食档案、菜单、收藏、做过和购物确认使用正式接口；未确认整周菜单草稿只留在本地 |
| 行程 | 正式闭环 | 复用 Project、Event、Task 与媒体引用，不新增平行 Trip 网络 DTO |
| 重要日 | 正式闭环（无设备推送） | 复用 `event_kind=important_date` 的全天 Event；年度投影、闰日和排序由服务端计算；单次日期的“已过期”由账号时区和日期推导，“已处理”只由用户明确标记并退出重要日、Today 与提醒，仍保留在日历历史；支持编辑、删除、标记已处理及即时撤销，提醒目前只形成服务端规则 |
| 购物 | 正式闭环 | 复用 `list_kind=shopping` 的 TaskList／Task；数量、品类、备注和食谱来源使用正式字段与来源引用 |
| 专注 | 部分接入 | Today 任务与内置 `focus` Tracker／Record 为正式数据；计时中状态和暂存想法只在当前页面。“标记任务完成”的选择当前未调用 Task 更新接口，保存后只写专注 Record |
| 记账 | 正式闭环 | 手工账单、月度统计和账单列表读取内置 `ledger` Tracker／Record；拍照／截图复用正式媒体 Capture、OCR／解析、可编辑确认和 Record 写入，不再展示模拟金额、预算或洞察 |
| 运动 | 部分接入 | 前台 GPS、路线与计时在设备会话内完成，用户确认后写入内置 `workout` Tracker／Record；原始坐标不上传，也不支持后台定位 |
| 复盘 | 正式闭环 | 使用 Weekly Review API、Operation 与 Proposal；AI 不可用时仍展示确定性指标 |

## 工程现状与目标态差异

| 主题 | 当前实现 | 文档中的演进方向 |
|---|---|---|
| 移动端路由 | `apps/mobile/src/app` | 所有路由继续由 Expo Router 管理；目录示例必须与仓库一致 |
| UI 组件与 Token | `apps/mobile/src/components/ui` 与 `apps/mobile/src/theme/tokens.ts` | 若未来建立 `packages/ui`，须先迁移并验证，不能把尚不存在的包写成当前依赖 |
| 图标 | Hugeicons 经 App 内 `components/ui/icon` 语义适配 | Feature 不直接依赖底层图标库；是否上移到共享包由真实复用需求决定 |
| UI／表单状态 | React `useState`、Context、Reducer 与页面数据层；服务端状态使用 TanStack Query | 当前未安装 Zustand 或 React Hook Form；引入前需有明确问题和迁移范围 |
| 本地持久化 | Token、心情草稿与 Capture 数据库密钥使用 `expo-secure-store`；Capture 元数据／队列使用按账号分库的 SQLCipher，媒体文件位于系统沙箱保护的应用 Documents 目录 | 当前只把该仓库用于 Capture；Web 不持久化 Capture 私有草稿，其他原型仍按各自边界处理 |
| 标准原生控件 | `@expo/ui`、`@react-native-community/slider` 经 App 内适配层使用 | Feature 继续只依赖项目适配组件 |
| TypeScript 任务 | pnpm workspace 与各包脚本，由根 Makefile 编排 | 当前没有 Turborepo 配置；只有出现多个包构建缓存需求后再评估 |
| 移动端测试 | Node 内置 Test Runner 的确定性测试，另有 ESLint 与 TypeScript 检查 | Maestro／完整 E2E 尚未成为当前根检查的一部分 |

这张表描述基线提交，不把“当前没有安装”解释为永久禁止。新增依赖或抽取共享包时，必须先更新架构决策、依赖边界与验证方式，再修改本页状态。

## 如何更新本页

只有状态跨级时才修改本页；页面内的小交互、样式或局部字段变化留在对应设计文档、契约或模块 README。更新时至少核对：

1. OpenAPI 是否存在且生成产物无漂移。
2. Go Handler／Application／Repository 和迁移是否已经落地。
3. 移动端是否通过生成 Client 使用正式数据，还是仍读 Fixture／进程内状态。
4. 正常、空、加载、错误、离线和冲突状态是否有相应实现或明确缺口。
5. AI 写入是否仍经过 Candidate／Proposal 与用户确认，且保留确定性手工路径。
6. 是否触发 H5、权限、第三方处理、账号删除、OTA 或应用商店申报门禁。

核对完成后更新“核对基线”和“核对日期”。不要在根 README、移动端 README 或新建进度文档中复制本表。
