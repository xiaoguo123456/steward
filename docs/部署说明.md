## 部署结构

steward 复用 huahuadog 的 ECS、ACR 和 SSH 密钥，但使用独立目录、端口和 Compose 项目。

| 环境 | 触发方式 | 服务器 Secret | 目录 | 宿主端口 |
|---|---|---|---|---|
| 测试 | `main` 推送后自动部署 | `TEST_SSH_HOST` | `/opt/steward-test` | `8088` |
| 生产 | 手工输入 main 分支 commit SHA | `PROD_SSH_HOST` | `/opt/steward-prod` | `8088` |

两个 Secret 复用 huahuadog 对应的测试、生产机器。两台机器上的 steward 都使用 `8088`，不占用 huahuadog 已使用的宿主机 80 端口。

移动 Web 镜像构建会在 Expo 导出前运行公开 H5 校验。测试构建使用 `staging` 模式检查固定路径、HTML 结构、无脚本、无用户 API 和无伪账号删除表单；生产工作流显式传入 `STEWARD_H5_RELEASE_MODE=production`，额外拒绝 `data-release-blocker`、“待确认”、“禁止生产发布”和 `noindex`。Android 生产 APK 与 production OTA 使用同一门禁，因此补齐正式内容前生产构建失败是预期安全行为。

入口路由：

- `/`：移动 Web。
- `/legal/*`、`/support`：由移动 Web 静态导出承载的公开法律与帮助 H5；不要求登录、不依赖 JavaScript。当前内容带生产阻塞标记，仅允许测试环境验证结构。
- `/v1/`：公共 API。
- `/admin/`：管理台。
- `/admin/v1/`：管理 API。
- `/healthz`、`/admin-healthz`：部署健康检查。

## 首次配置

### 1. ACR 与 GitHub Secrets

ACR 建立三个仓库：

- `steward-backend`
- `steward-mobile-web`
- `steward-admin-web`

GitHub 仓库配置以下 Secrets，值可复用 huahuadog：

```text
ACR_REGISTRY
ACR_PULL_REGISTRY
ACR_NAMESPACE
ACR_USERNAME
ACR_PASSWORD
TEST_SSH_HOST
PROD_SSH_HOST
SSH_KEY
ANDROID_TEST_KEYSTORE_BASE64
ANDROID_TEST_KEYSTORE_PASSWORD
```

生产服务器部署和 Android 正式发布都使用 GitHub `production` Environment；需要人工审批时，在该 Environment 配置 reviewer。Android 正式发布还会读取：

```text
ANDROID_PRODUCTION_KEYSTORE_BASE64
ANDROID_PRODUCTION_KEYSTORE_PASSWORD
```

签名别名固定为 `steward-test` 和 `steward-production`。JKS 文件的 Base64 使用单行文本保存到 Secret，原始生产签名和密码还必须离线备份。

移动端 OTA 还需要在 GitHub 的 `test` 与 `production` Environment 配置：

```text
EXPO_TOKEN
EXPO_PROJECT_ID
EXPO_UPDATES_CERTIFICATE_BASE64
EXPO_UPDATES_PRIVATE_KEY_BASE64
```

`EXPO_TOKEN` 使用只具备目标 Expo Project 发布权限的机器人 Token；`EXPO_PROJECT_ID` 使用真实 UUID。证书公钥会嵌入 APK，私钥只存 GitHub Environment Secret 和受控离线备份，不进入仓库、构建产物或日志。EAS Update 端到端代码签名需要确认 Expo Production／Enterprise 套餐；未满足时正式 APK 构建和 OTA 发布保持阻塞，不能降级为无签名生产更新。

Expo Project 的 EAS Environment 还要设置：`preview` 的 `EXPO_PUBLIC_API_URL=https://test-steward.qhzhiyin.com`，`production` 的 `EXPO_PUBLIC_API_URL=https://steward.qhzhiyin.com`。GitHub Environment 控制发布权限和 Secret，EAS Environment 控制 OTA 打包时注入的公开环境变量，两者用途不同，必须同时配置。

### 2. 数据库、Redis 与 OSS

复用 huahuadog 的同一套实例，但做环境隔离：

| 环境 | PostgreSQL 数据库 | 运行账号 | 后台账号 | 迁移账号 | Redis DB | OSS 前缀 |
|---|---|---|---|---|---|---|
| 测试 | `steward_test` | `steward_t_app` | `steward_t_admin` | `steward_t_mig` | `5` | `steward/test` |
| 生产 | `steward_prod` | `steward_p_app` | `steward_p_admin` | `steward_p_mig` | `6` | `steward/prod` |

RDS 还要预建不实际登录的 ACL 账号 `steward_app`、`steward_admin`，供迁移保存公共权限定义。迁移 `00031` 会撤销它们对部署库的连接权，并把权限授给环境专属账号。RDS 私网连接使用 `sslmode=disable`。

API 与 Worker 启动时会校验当前环境应用账号是否具备登录、聚合和账号删除所需的 `SECURITY DEFINER` 函数执行权限。权限缺失会让容器启动失败并触发部署回滚；新迁移新增或重建此类函数时，必须在同一条向前迁移中同步授权环境账号。

Redis Pub/Sub 不按逻辑 DB 隔离，因此测试、生产还必须分别设置 `STEWARD_STREAM_NAMESPACE=steward-test` 和 `steward-prod`。

OSS Bucket 保持私有读写；对象物理键统一落在 `steward/` 下。Bucket CORS 允许 Web 域名的 `PUT`、`GET`、`HEAD`，并暴露 `ETag`。

跑步底图单独放在公开 CDN 前缀 `steward/maps/`，测试和生产共用版本化 PMTiles，不重复存储。Bucket 仍保持私有；CDN 对该前缀免 URL 鉴权，并开启 Range 回源、跨域响应头和一年不可变缓存。发布工具见 `tools/maps/`。用户轨迹不得写入该公开前缀。

### 3. 服务器环境文件

```bash
mkdir -p /opt/steward-test/deploy /opt/steward-prod/deploy
```

分别把模板复制到服务器并填入真实值：

```text
.env.test.example       → /opt/steward-test/.env.test
.env.production.example → /opt/steward-prod/.env.production
```

随后执行：

```bash
chmod 600 /opt/steward-test/.env.test
chmod 600 /opt/steward-prod/.env.production
```

环境文件不由 CI 上传，也不提交到 Git。管理员口令散列用 `make admin-passwd` 生成。

### 4. ALB

steward 复用 `weishen` ALB（`alb-0ta48ecgc5jvvu40pv`）。

| 环境 | 域名 | 服务器组 | 后端 | 健康检查 |
|---|---|---|---|---|
| 测试 | `test-steward.qhzhiyin.com` | `测试-steward` | 测试 ECS `8088` | `HEAD /healthz` |
| 生产 | `steward.qhzhiyin.com` | `生产-steward` | 生产 ECS `8088` | `HEAD /healthz` |

HTTPS `443` 监听按域名转发到对应服务器组；HTTP `80` 监听使用现有全局规则返回 `301` 并保留原路径和查询参数。DNS CNAME 目标为：

```text
alb-0ta48ecgc5jvvu40pv.cn-beijing.alb.aliyuncsslb.com
```

## 发布

- 测试服务器：合并或推送到 `main` 后自动运行“测试环境部署”。
- 测试 APK：只手工运行“Android 测试包”，输入 `main` 上的 commit SHA 和准备验证的 App 版本；产物作为 Actions Artifact 保留 30 天。推送和测试服务器部署不自动生成 APK，本地 UI 调试优先使用 Emulator 热更新。
- 生产服务器：手工运行“生产环境部署”，只输入已在 `main` 的 commit SHA，不生成 APK。
- 生产 APK：需要发布 App 时，单独手工运行“Android 正式发布”，输入已在 `main` 的 commit SHA 和 App 版本号，产物保存到 `android-v<版本号>` GitHub Release。
- 首个正式移动端版本统一为 `1.0.0`，并已包含 `expo-local-authentication` 原生代码和生物识别权限。首个包含该能力的 iOS／Android 包必须走原生构建与商店审核，不能发布到其他 runtime 的 OTA；发布前真机检查冷启动、后台任务预览、认证取消／失败／锁定、设备密码回退及关闭开关，并复核 Face ID 用途说明、个人信息清单和商店隐私申报。Android 正式发布工作流独立生成递增的 `versionCode`，用户可见版本仍使用 `1.0.0`。

正式 App 使用新接口前，先完成兼容后端的生产部署，再运行“Android 正式发布”。

OTA 使用手工“移动端 OTA 更新”工作流：先选择 `test` 并对匹配版本的测试 APK 完成冷启动更新验证，再选择 `production` 从 10% 灰度开始。工作流只接受 `main` 上、位于目标原生包提交之后的更新提交，并通过变更范围检查与签名后发布。观察无异常后使用 EAS CLI／Dashboard 提升至 100%；异常时立即停止灰度并执行 `eas update:rollback` 回到上一稳定更新或安装包内置版本，同时检查本地持久化状态是否允许安全回退。完整决策见 `docs/ADR-028-移动端OTA更新.md`。

测试 App 名称为“清单测试”，包名为 `com.aisteward.mobile.test`；生产 App 名称为“清单”，包名为 `com.aisteward.mobile`，两者可同时安装。每个 APK 同时生成 SHA256 文件，测试和生产使用不同的固定签名。

流水线先执行代码生成、空库迁移和 `make check`，再构建三个镜像并推送 ACR，最后通过 SSH 更新 Compose。部署使用不可变短 SHA 标签；健康检查失败会回滚到 `.last-good-tag`。

测试 API 返回 500 时，先从响应 `X-Request-Id` 或响应体 `meta.request_id` 取得请求 ID，再手工运行“测试环境部署”工作流并填写“可选：只读取该请求 ID 的测试 API 脱敏错误日志”。填写请求 ID 后，工作流只查询最近 6 小时内该请求的 API 日志，不执行检查、构建或部署；输入只接受 `req_` 开头的小写字母数字标识，避免把手机号、Token、验证码或任意日志检索条件带入远程命令。

数据库迁移只向前执行。包含不兼容迁移时，自动回滚镜像不能回滚数据库，发布前必须准备单独的前滚或数据库恢复方案。

测试环境的 API、Worker 和 migration-job 均强制使用 `STEWARD_SMS_PROVIDER=dev` 和 6 位 `STEWARD_DEV_SMS_CODE`，不调用阿里云短信；生产环境使用 `STEWARD_SMS_PROVIDER=aliyun`，并保持 `STEWARD_DEV_SMS_CODE` 为空。阿里云 AccessKey、签名和模板只写入生产服务器环境文件，不进入 GitHub Secrets 或仓库。

### 测试账号的时光数据

测试环境部署包含 Memory Moments 迁移后，可以通过正式登录、媒体上传和时光接口为指定测试账号写入一组合成照片数据：

```bash
STEWARD_MEMORY_SEED_PHONE='<测试账号手机号>' \
STEWARD_DEV_SMS_CODE='<测试环境开发验证码>' \
pnpm seed:test:memories
```

脚本固定拒绝非 `https://test-steward.qhzhiyin.com` 主机，不输出手机号、Token 或签名地址，并按日期与标题跳过已经存在的同一批数据。它只用于用户明确指定的测试账号；不得把脚本改为生产造数，也不得把真实个人照片放入仓库资源。

### 测试账号的心情日历数据

需要验收心情首页的最近七天、内联月历、同日多篇计数、时间线与花园时，可以通过正式心情日记接口为指定测试账号写入最近 28 天的合成日记：

```bash
STEWARD_MOOD_SEED_PHONE='<测试账号手机号>' \
STEWARD_DEV_SMS_CODE='<测试环境开发验证码>' \
pnpm seed:test:mood-journal
```

脚本固定拒绝非测试域名，只新增缺少的同标题同日条目，并在结束前从正式列表与月历接口读回校验。所有合成日记均设置为“不参与 AI 回望”和“不出现在往日回忆”，不会被发送给 Provider；脚本不输出手机号、Token 或日记正文，也不得用于生产账号。

### 测试账号的当天重要日数据

需要验收重要日首页的“今天”、一次性处理动作、年度重复差异和首页到点提醒时，可以通过正式 Event 接口写入两条一次性重要日和一条年度生日：

```bash
STEWARD_IMPORTANT_DATE_SEED_PHONE='<测试账号手机号>' \
pnpm seed:test:important-dates
```

脚本固定拒绝非测试域名，从测试环境验证码响应完成登录，不输出手机号、验证码或 Token；相同标题的活动条目会更新到账号当地今天，并在结束前从正式重要日读模型读回校验。设置 `STEWARD_IMPORTANT_DATE_VERIFY_HANDLED=1` 时，脚本还会执行一次可恢复的“标记已处理 → 退出活动读模型 → 撤销恢复”检查；该检查只应在包含重要日处理状态的后端版本部署后运行。
